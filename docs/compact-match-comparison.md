# Compact match comparison

The shared MatchRotationComparison replaces repeated per-period callup editors with one roster, adjacent pitch previews, and an always-open player matrix. Coach cells edit starters/bench using the existing manual/automatic rotation helpers; the first period stays manual. Automatic rotation retains its existing small-sided-format scope. Fourth-period persistence, half-third periods, alternatives and actual reports keep their existing data model. Duration, alternatives and training attendance are secondary details. Mobile places the matrix before the pitches; previews can be enlarged.

The matrix labels planned equivalent periods and planned minutes separately from actual report minutes. Two half-periods equal one period; unequal segments use their real proportions. Missing/invalid reports are unknown, never zero. Actual substitutions are intersected with each segment, including recorded recovery at the end of a full period.

Parents see the selected session child's row only in Attendance / Minutaggio, including planned upcoming callups and historical matches. The API projects only that player: no peer row, position, raw match plan, report or technical notes. Public called-up names remain available through the existing callup view. Legacy embedded plans are removed from public fixture notes. Client playerId parameters cannot change the child selected in the authenticated session.

Managers receive all called-up players for the assigned team, including supplementary callups, in read-only mode. Existing club, section, membership and team-assignment checks remain. The generic raw-plan match list rejects parent and manager profiles; their dedicated endpoints provide the authorized projections. Other staff retain the existing match list.

Validation: API-zod/frontend/API typechecks; frontend and API production builds; scripts/test-match-period-rotation.cjs; scripts/test-match-rotation-views.cjs; scripts/test-match-rotation-access.cjs. The access test bundles actual Express handlers and Drizzle with isolated PGlite data; simulated sessions verify child projection, tampered query, public callups, unauthorized roles/teams/clubs/sections and generic endpoint protection. No production data or notifications are written. Interactive browser verification remains pending because the installed Browser plugin lacks its required control skill.
